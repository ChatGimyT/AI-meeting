# 🪑 AI Editorial Boardroom — محرك كتابة المحتوى بطاولة اجتماعات

أتمتة **n8n** واحدة تكتب مقالات SEO (وبوستات سوشيال ميديا) عبر **ورشة تحرير كاملة من وكلاء ذكاء اصطناعي**:
مجلس تحرير يحسم، ورشة كتابة تنفّذ، لجنة نقد من ٩ أعضاء تهاجم، فريق استشهادات يبحث فعليًا على الإنترنت،
ومفتش آلي يقيس ولا يجامل — والمقال **يلف على الطاولة أكثر من مرة** حتى يستوفي كل المعايير أو يُسلَّم مع تقرير تحفّظات.

> **الملفات الجاهزة للاستيراد:**
> - [`dist/ai-editorial-boardroom.json`](dist/ai-editorial-boardroom.json) — النسخة العامة (Anthropic افتراضيًا، وتعمل مع أي مزوّد)
> - [`dist/ai-editorial-boardroom-deepseek.json`](dist/ai-editorial-boardroom-deepseek.json) — **نسخة DeepSeek**، مربوطة مسبقًا بالكريدينشال ومضبوطة على الكتابة قسمًا بقسم

---

## ما الذي يميّز هذا المحرك؟

| المشكلة المعتادة في أتمتة كتابة المقالات | الحل هنا |
|---|---|
| برومبت واحد ضخم يُنتج مقالًا ثم ينتهي | **دورات تحرير حقيقية**: نقد → حسم → تعديل → إعادة فحص، حتى العتبة |
| النموذج يقيّم نفسه فيجامل نفسه | **فصل الكاتب عن الناقد**: ٩ نقاد مستقلون، كل واحد مسؤول عن بنود محددة فقط |
| «راجع عدد الكلمات» يُترك للنموذج | **مفتش آلي (كود)** يقيس ٢٣ فحصًا رقميًا لا يستطيع أحد الجدال فيها |
| إحصائيات مختلقة وروابط ميتة | فريق بحث يستخدم **web search** فعليًا + **فحص HTTP لكل رابط** + مدقق حقائق يرفض |
| المراجعون يتناقضون فيدور المقال بلا نهاية | **رئيس مجلس يحسم التعارض كتابةً** ويرفض الملاحظات الضعيفة، وموجز تعديل واحد ≤ ١٢ بندًا |
| الأتمتة مخصّصة لمشروع واحد | **ملفات تعريفية (Profiles)** بالوراثة: بدّل الملف → بدّل المشروع كله |

## المدخلات من شيت جوجل — «زرار» التشغيل

الشيت هو لوحة التحكم: تملأ صفًا، تعلّم ✅ في عمود **تشغيل**، فيلتقطه المحرك خلال دقيقة
ويكتب المقال والتقارير و**المقارنة بالمقال المرجعي** في الصف نفسه.

```
الورقة1 ──✅ تشغيل──▶ ⏱️ Sheet Poll ──▶ 🎯 Pick Pending Row ──▶ [ ورشة التحرير كاملة ]
                                                                        │
   الحالة · الدرجة · المخالفات · المقال · التقرير · المحضر ◀── 📝 Sheets: Write Results
```

## التشغيل في ٣ دقائق

1. **استورد الملف** في n8n: `Workflows → … → Import from File` واختر `dist/ai-editorial-boardroom.json`.
2. **أنشئ Credential** من نوع **Header Auth** وسمّه `LLM API Key`:
   - **Anthropic**: `Name = x-api-key` ، `Value = مفتاحك`.
   - **OpenAI**: `Name = Authorization` ، `Value = Bearer sk-...` ثم غيّر `provider` و`url` و`model` داخل عقدة `📚 Profiles Registry`.
3. **اربط الـ Credential** بأي عقدة `🧠 LLM · …` (n8n سيقترحها تلقائيًا على البقية).
4. عدّل عقدة **`📥 Brief — EDIT ME`** ثم اضغط **Execute Workflow**.

تفاصيل أوفى: [`docs/SETUP.md`](docs/SETUP.md)

### تشغيل على DeepSeek

استورد `dist/ai-editorial-boardroom-deepseek.json` — الكريدينشال مربوط مسبقًا (`UtZ5Hq48pibn5oXX`)
والملف التعريفي الافتراضي `rabeh_article_ar_deepseek`.

هذه النسخة تختلف جوهريًا لأن سقف مخرجات DeepSeek 8192 توكن، ومقال عربي من ٢٠٠٠ كلمة يقترب منه:
**الكتابة تصير قسمًا بقسم** بدل نداء واحد، مع أهداف رقمية لكل قسم وقائمة عناصر محمية من الحذف.
التفاصيل والقياس في [`docs/QUALITY-PLAN.md`](docs/QUALITY-PLAN.md).

## مسار المقال داخل المحرك

<div dir="ltr">

```
المدخلات ─→ جلسة إحاطة ─→ تثبيت المخطط ─→ بحث + فحص روابط + تدقيق حقائق
    │
    └─→ كتابة ─→ تمريرة سرد ─→ تمريرة لغة ─→ 🔍 مفتش آلي ─→ 🗣️ طاولة النقد (٩)
                                                  ↑                  │
                                                  │                  ▼
                                                  │            🪑 حسم المجلس
                                                  │                  │
                                                  │                  ▼
                                                  │             🚪 البوابة
                                                  │        ┌─────────┼──────────┬───────────┐
                                                  └── revise      restart    approve    exhausted
                                                        │           │           │           │
                                                        │           └→ إعادة بناء من المخطط │
                                                        └───────────────────────┘           │
                                                                              ⚖️ تدقيق نهائي ─→ 📦 حزمة النشر
```

</div>

**البوابة لا تصدّق رئيس المجلس على عماه** — تتحقق بنفسها من ثلاثة شروط:
كل بند ≥ العتبة (٨/١٠)، صفر أخطاء حرجة، والمفتش الآلي ناجح.
وأي مخالفة للمفتش الآلي تدخل موجز التعديل **إجباريًا** مهما قال المجلس.

## حزمة التسليم

كل تشغيلة تُخرج كائن JSON واحدًا يحتوي:

| الحقل | المحتوى |
|---|---|
| `article_markdown` | المقال كاملًا مع الـ frontmatter |
| `meta` | H1، Meta Title، Meta Description، Slug، عدد الكلمات، زمن القراءة |
| `json_ld` | Schema جاهزة: `Article` + `FAQPage` + `citation` لكل مصدر |
| `sources` | جدول المصادر المعتمدة (جهة، عنوان، رابط مباشر، الرقم المستخدم) |
| `link_report` | حالة HTTP لكل رابط استُشهد به |
| `scorecard` + `final_scores` | تقييم كل بند من ١٠ مع سبب الدرجة |
| `opportunities` / `critical_issues` | فرص التحسين والأخطاء المانعة للنشر |
| `mechanical` | نتيجة ٢٣ فحصًا رقميًا بالتفصيل |
| `audit_report_markdown` | تقرير التدقيق النهائي جاهزًا للعرض |
| `meeting_minutes_markdown` | **محضر الاجتماع كاملًا**: من قال ماذا، وما التعارضات التي حُسمت، وما الملاحظات التي رُفضت ولماذا |
| `update_report` | تقرير التحديث (في ملف تحديث المقالات القائمة) |

## إعادة استخدامه في أي مشروع آخر

المحرك **لا يعرف شيئًا عن رابح ولا عن السيو**. كل ما يخص المشروع يعيش في عقدة `📚 Profiles Registry`.

<div dir="ltr">

```js
export default {
  id: 'my_client_en',
  extends: 'rabeh_article_ar',        // يرث كل الشخصيات والقواعد
  brand:  { name: 'Acme', markets: ['UK'], /* … */ },
  rules:  { word_count: { min: 1200, max: 1500 } },
  roster: { lead_writer: { system: 'اكتب بالإنجليزية بنبرة…' } },
  seats:  { panel: ['seo_auditor', 'red_team', 'language_critic'] }
};
```

</div>

ثلاثة ملفات جاهزة داخل الصندوق:

| الملف | الاستخدام |
|---|---|
| `rabeh_article_ar` | مقال SEO عربي جديد (١٨٠٠–٢٠٠٠ كلمة) |
| `rabeh_refresh_ar` | **تحديث** مقالة منشورة دون إعادة كتابتها (٢٠٠٠–٢٦٠٠ كلمة + تقرير تحديث) |
| `social_posts_ar` | حزمة بوستات سوشيال ميديا بحدود أحرف وهاشتاجات لكل منصة |
| `rabeh_article_ar_deepseek` | نفس الأول مضبوطًا على DeepSeek (كتابة مُجزَّأة + أهداف لكل قسم) |
| `social_posts_deepseek` | بوستات على DeepSeek |

دليل التوسعة خطوة بخطوة: [`docs/EXTENDING.md`](docs/EXTENDING.md)

## التطوير والاختبار

<div dir="ltr">

```bash
npm run build:all  # يجمّع نسختي dist (العامة + DeepSeek)
npm run validate   # فحص بنيوي للملف قبل الاستيراد
npm test           # بناء + فحص + محاكاة الملفات التعريفية الخمسة (بلا تكلفة API)

# ── قياس الجودة ──
npm run grade   -- --article=x.md --brief=benchmark/briefs/google-ads-ar.json
npm run compare -- --gold=benchmark/gold/google-ads-ar.md --candidate=x.md --brief=...
npm run bench   -- --profile=rabeh_article_ar_deepseek --judge     # يحتاج مفتاح API
```

**المقارنة داخل n8n**: عقدة `📐 Compare vs Reference` تقيس كل مقال ناتج مقابل المقال المرجعي
(الفحوص الرقمية + بصمة الأسلوب: طول الفقرة، تنوع المفردات، أدوات الربط، جمل «نحن/نقدم»،
كثافة الأرقام، العبارات الآلية المكشوفة) وتكتب الجدول في الشيت — بلا حاجة إلى الطرفية.

**قياس الجودة**: يوجد مقال مرجعي مكتوب يدويًا وفق المعايير نفسها بخمسة مصادر حقيقية
(`benchmark/gold/`) يحقق **100%** على الفحص الآلي، ومقال ضعيف نموذجي (`benchmark/samples/`)
يحقق **55%** — فيصير الفارق بين «جيد» و«رديء» رقمًا لا انطباعًا.
البروتوكول كاملًا في [`docs/QUALITY-PLAN.md`](docs/QUALITY-PLAN.md).

</div>

`tools/simulate.mjs` محاكي n8n مصغّر ينفّذ الـ workflow فعليًا بنموذج وهمي،
فيتحقق من تدفق البيانات ودورة التعديل ومنطق البوابة **قبل أن تدفع دولارًا واحدًا لـ API**.

## التكلفة التقريبية

|---|---|
| نداءات النموذج في دورة واحدة ناجحة | ~٢٠ |
| كل دورة تعديل إضافية | +١١ |
