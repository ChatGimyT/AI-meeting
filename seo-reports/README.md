# أوتوميشن تقارير SEO — العوجان وشوق (أسبوعي + شهري)

أربع workflows في n8n بتسحب ترتيب الكلمات المفتاحية من Google Search Console،
بتحدّث شيت أرشيف، بتبني عرض Google Slides، وبتبعت تقرير بالإيميل.

الملفات الجاهزة للاستيراد في **[`dist/`](dist)**.

## المشاكل اللي الإصدار ده بيحلّها

1. **أرقام كانت بتطلع فاضية** رغم إنها موجودة في GSC — ٧ أسباب جذرية اتصلّحت،
   وبقى فيه ٦ طبقات تحقق وبوابة جودة بتوقف الرن بدل ما يطلّع تقرير ناقص.
2. **تحديث الكلمات** من ملف الإكسل: العوجان ٢٤ → **٣٥** كلمة، شوق ١٣ → **٢٥**،
   ومعاها حجم البحث الشهري لكل كلمة.
3. **تنبيه فشل Search Console مكانش بيقول السبب** — بقى بيجيب قائمة المواقع اللي
   الحساب شايفها ويقولك السبب المحدد والخطوة المطلوبة.
4. **الإيميل مابيوصلش على جيميل** — الأوتوميشن بقى بيقرا رد سيرفر SMTP الحقيقي،
   بيعيد الإرسال فرديًا لأي مستلم اترفض، وبيبعت تقرير حالة توصيل فيه السبب الحرفي.
5. **أرقام مش مطابقة لواجهة Search Console** — التقرير كان بيقول «POS 10 / IMP 1»
   لكلمة الواجهة بتقول عنها موضع 20.9. السبب: الكود كان بياخد **أقل موضع بين كل
   صفحات الموقع** وظهور الصفحة دي لوحدها. دلوقتي: الكلمة اللي معاها رابط بتتقاس
   على صفحتها بالظبط، واللي من غير رابط بتتقاس على الموقع كله بمتوسط موزون بالظهور
   — نفس حساب الواجهة. تفاصيل كاملة في [docs/PLAN.md](docs/PLAN.md#المشكلة-الخامسة-أرقام-التقرير-مش-مطابقة-لواجهة-search-console).

التفاصيل الكاملة في **[docs/PLAN.md](docs/PLAN.md)**.

## الأوامر

```bash
python3 seo-reports/extract-keywords.py   # الكلمات من الإكسل → JSON
node seo-reports/build.mjs                # بناء ملفات n8n الأربعة
node seo-reports/validate.mjs             # ١٩ فحص ساكن على الملفات
node seo-reports/test.mjs                 # ٨٧ اختبار سلوكي
```

أو دفعة واحدة: `npm run seo:all`

## إزاي التقرير بيحسب الرقم — ومطابقته بالواجهة

| الحالة | الرقم في التقرير | الفلتر المقابل في Search Console |
|--------|------------------|-----------------------------------|
| الكلمة معاها رابط صفحة والصفحة ظاهرة | موضع وظهور **الصفحة دي** | Query = exact + **Page = exact URL** |
| الكلمة من غير رابط، أو الصفحة مش ظاهرة | **الموقع كله**: ظهور = المجموع، موضع = المتوسط الموزون بالظهور | Query = exact بس |

في الحالتين: `Search type: Web` + فلتر الدولة + بيانات نهائية (`final`).

كل سلايد فيه سطر «نطاق القياس» بيقول الحالة دي، وكل إيميل فيه خطوات المراجعة
بالفلاتر بالحرف. الكلمات من غير صفحة مستهدفة عليها `*` في جدول الإيميل.

**عايز رقم كلمة يبقى على صفحة معيّنة؟** حط رابطها في **عمود F** في
`keywords/source.xlsx` قصاد الكلمة، وشغّل `npm run seo:keywords && npm run seo:all`.

## قاعدة مهمة

**متعدّلش الكود من داخل n8n.** عدّل في `nodes/` أو `keywords/` واعمل build —
غير كده التعديل هيضيع أول مرة تبني تاني.

الاستثناء الوحيد: نود **`Search Volume`** مقصود يتعدّل من داخل n8n كتعديل
يدوي فوق قيم الإكسل.

## الإعدادات اللي هتحتاج تغيّرها

كلها في نود `Config` في كل workflow (والمصدر في `nodes/config.js` + `build.mjs`):

| الإعداد | القيمة | يعني إيه |
|---------|--------|----------|
| `MIN_COVERAGE` | `0.98` | أقل نسبة خانات مكتملة قبل ما نكتب على الشيت |
| `MAX_HOLES` | `12` | أقصى عدد خانات فاضية مسموح بيه |
| `PAGE_MATCH` | `prefer` | `strict` = الصفحة المحددة بس، `prefer` = وإلا رقم الموقع كله للكلمة |
| `GSC_ROW_LIMIT` | `1000` | أقصى عدد صفحات بنطلبها لكل كلمة |
| `VOLATILE_TAIL` | `2` | آخر كام عمود مسموح لسحبة جديدة تعدّل أرقامه |
| `COLUMNS` | `15` | عدد الأعمدة في التقرير والسلايدز |
| `REFETCH_LAST` | `= COLUMNS` | بيعيد سحب كل الأعمدة كل مرة (الشيت أرشيف بس) |

## الكريدنشيالز

| المشروع | حساب جوجل | SMTP |
|---------|-----------|------|
| العوجان | `rabeh.seven.b` (`zqpCaDcnpV6T6BqM`) | `Rabeh SMTP` |
| شوق | `Google` (`eAFsFY5y1jlvRQZZ`) | `Rabeh SMTP` |

**المشروعين على حسابين جوجل مختلفين.** حساب العوجان مش شايف موقع شوق في
Search Console والعكس — أي خلط بينهم بيوقف الرن بخطأ 404. `validate.mjs`
بيتأكد من ده في كل بناء.
