# خطة الاختبار

الخطة دي **منفّذة كود** مش ورق. كل بند تحت ليه اختبار حقيقي بيشغّل نفس
كود النودات المرفوع في `dist/*.json` — مش نسخة تانية منه.

```bash
python3 seo-reports/extract-keywords.py   # الكلمات من الإكسل
node seo-reports/build.mjs                # بناء ملفات n8n
node seo-reports/validate.mjs             # فحص ساكن على الملفات
node seo-reports/test.mjs                 # ٧٥ اختبار سلوكي
```

كله لازم يعدّي قبل أي استيراد في n8n.

---

## المستوى ١ — فحص ساكن (`validate.mjs`)

بيمسك الأخطاء اللي مابتظهرش غير وقت الرن الحقيقي:

| # | الفحص |
|---|-------|
| ١ | مفيش أسماء نودات مكررة |
| ٢ | كل وصلة بتشاور على نود موجود |
| ٣ | مفيش نود معزول (غير التريجرز) |
| ٤ | كود كل نود بيترجم من غير أخطاء + مفيش placeholder فاضل |
| ٥ | كل `$('X')` في الكود بيشاور على نود موجود **وبيشتغل قبله فعلاً** |
| ٦ | نفس الفحص على تعبيرات نودات HTTP والإيميل |
| ٧ | كل نود HTTP/Email معاه كريدنشيال |
| ٨ | `GSC Query` و `GSC Retry Query`: `alwaysOutputData=false` + `onError=continueRegularOutput` + إعادة محاولة ≥ ٣ |
| ٩ | كل نودات الإيميل: `emailFormat=both` + نسخة نصية + `appendAttribution=false` + `fromEmail` باسم عرض |
| ١٠ | `Write To Sheet` بيكتب `$json.sheetValues` (مش تعبير طويل) |
| ١١ | بوابة الجودة موصولة صح: نجاح → الكتابة، فشل → التنبيه |
| ١٢ | عدد الكلمات = عدد خانات `Search Volume` |
| ١٣ | مفيش أي أثر للـ AI (`deepseek` / `choices[0]` / `Build Prompt`) |
| ١٤ | تنبيه فشل GSC تشخيصي: بيعدّي على `List GSC Sites` وبياخد نصه من `GSC Diagnose` |

الفحص رقم ٨ مهم بالذات: لو حد فتح `alwaysOutputData` تاني على `GSC Query`،
البناء بيرفض — لأن ده كان أحد أسباب تحويل الفشل لـ `-`.

## المستوى ٢ — اختبارات سلوكية (`test.mjs`)

الاختبارات بتشتغل على محاكي مصغّر لبيئة نود الكود في n8n
(`tests/harness.mjs`): بيوفّر `$('اسم النود')` و `$input` و `$json` وبيشغّل
`jsCode` المستخرج من ملف `dist` نفسه.

### ١) سحب الأرقام — التفريق بين "مفيش ظهور" و"فشل"

| الحالة | المتوقع |
|--------|---------|
| رد سليم فيه ترتيب | الرقم يتكتب مقرَّب لخانة عشرية |
| رد سليم من غير ظهور | `-` (مش خانة فاضية) |
| طلب فشل بـ 429 | خانة **فاضية**، وسبب الفشل يتسجّل |
| صف راجع بـ `position = 0` | يتعامل كـ "مفيش ظهور" مش كرقم |

### ٢) الربط بين الطلب والرد — السبب الرئيسي للأرقام الفاضية

| الحالة | المتوقع |
|--------|---------|
| ردود جاية بترتيب مقلوب | كل رد يرجع لطلبه بـ `pairedItem` |
| رد واحد بس لكل الطلبات (فشل النود كله) | الست خانات فاضية، **ولا واحدة `-`** |
| رد يتيم من غير `pairedItem` | يتجاهل، ما يزحلقش الباقي |

الحالة التانية دي بالظبط اللي كانت بتحصل مع توكن منتهي — الكود القديم كان
بيخلي طلب واحد بس ياخد رد والباقي فاضي من غير تنبيه.

### ٣) المحاولة التانية

| الحالة | المتوقع |
|--------|---------|
| ٢ طلب فشلوا من ٦ | `Collect Results` يطلّع الاتنين دول بس |
| كل الطلبات نجحت | عنصر واحد بـ `__retry=false` — فرع الإعادة مايفتحش |
| المحاولة التانية نجحت | الخانة تتملا وعدد الفاضي = ٠ |
| المحاولة التانية فشلت وكانت الأولى ناجحة | النتيجة الناجحة تفضل |

### ٤) مطابقة الصفحة المستهدفة

| الحالة | المتوقع |
|--------|---------|
| اختلاف في `www` / السلاش / حالة الحروف | يتطابق برضه |
| الصفحة المستهدفة مش ظاهرة | ياخد **أعلى ترتيب** (مش أعلى كليكات) ويسجّل ملاحظة |
| وضع `strict` والصفحة مش ظاهرة | `-` مؤكدة |

### ٥) حماية الأرشيف

| الحالة | المتوقع |
|--------|---------|
| طلب فشل + الأرشيف فيه رقم | رقم الأرشيف يرجع، مش خانة فاضية |
| عمود **قديم** رجع "مفيش" + الأرشيف فيه رقم | الأرشيف يكسب + شبهة تتسجّل |
| **آخر** عمود رجع "مفيش" | يتحدّث لـ `-` (لسه ممكن يتغير) |
| فشل قراءة الشيت | البوابة توقف الرن قبل أي كتابة |

### ٦) قراءة الشيت وتحويل الأرقام

| الحالة | المتوقع |
|--------|---------|
| خانة فاضية مقابل خانة فيها `-` | `filled=false` مقابل `filled=true, position=null` |
| `٤٫٥` و `١٬٢٣٤` | `4.5` و `1234` |
| أعمدة ناقصة في آخر الصف (جوجل بيقصّها) | تتقري "ما اتسحبتش" |
| فشل الجلب | `__sheetError` مش شيت فاضي |
| مقاس الشيت القديم | يتسجّل بالظبط للتبطين |

### ٧) الكتابة على الشيت

| الحالة | المتوقع |
|--------|---------|
| الشيت القديم ٤٠ صف × ٦٠ عمود والجديد أصغر | الكتابة تغطي ٤٠×٦٠ والزايد يتكتب فاضي |
| ترويسة الشيت | `Country, Section, Keyword, Page, Article, …` |
| خانة فشلت | تتكتب فاضية — **الترتيب والظهور الاتنين**، مش صفر |

### ٨) بوابة الجودة

| الحالة | المتوقع |
|--------|---------|
| كل الخانات مسحوبة | البوابة تفتح، التغطية = ١٠٠٪ |
| خانتين فشلوا من ٦ | البوابة تقفل + التنبيه فيه `429` الحرفي |
| الفاضي فوق `MAX_HOLES` | البوابة تقفل |
| ترتيب = ٤٠٠٠ | البوابة تقفل (رقم خارج المدى) |
| عدد الصفوف ≠ عدد الكلمات | البوابة تقفل |
| اختلاف صفحة بس | الرن يكمل + ملاحظة في الإيميل |

### ٩) آخر يوم فيه بيانات عند جوجل

| الحالة | المتوقع |
|--------|---------|
| رد فيه تواريخ | ياخد الأحدث، `source = gsc` |
| الطلب فشل | يرجع لـ `LAG_DAYS`، يسجّل السبب |
| جوجل رجّع تاريخ في المستقبل | يتقص لإمبارح |

### ١٠) بناء الفترات المطلوبة

| الحالة | المتوقع |
|--------|---------|
| شهري، آخر بيانات `2025-09-05` | آخر شهر = `2025-08`، سبتمبر مستبعد |
| شهري، آخر بيانات `2025-08-29` | آخر شهر = `2025-07` (أغسطس لسه ناقص) |
| أسبوعي | آخر أسبوع `endDate ≤ آخر يوم بيانات` |
| كل الطلبات | `taskId` فريد + `taskIndex` رقمي |
| `REFETCH_LAST = 1` وأرشيف كامل | طلب واحد بس |

### ١١) قايمة المستلمين

| الحالة | المتوقع |
|--------|---------|
| إيميلات جيميل | تفضل في القايمة زي أي إيميل |
| نفس العنوان في To و CC | يتشال من CC |
| عنوان بصيغة غلط | يتشال ويتسجّل، الباقي يتبعت |
| إيميل التنبيه التقني | عناوين دومين المُرسِل |
| مفيش عنوان على الدومين | يرجع للمُرسِل نفسه |

### ١٢) التأكد من توصيل الإيميل

| الحالة | المتوقع |
|--------|---------|
| السيرفر رفض عنوان الجيميل | إعادة إرسال فردية + تنبيه فيه `550` |
| السيرفر قبل الكل | مفيش إعادة |
| مستلم سكت عنه السيرفر | يتحسب ناقص |
| السيرفر مرجّعش قوايم | مابنبعتش مرتين |
| `"الاسم <إيميل>"` | يتقارن صح |
| الإرسال نفسه وقع (`535`) | كل المستلمين يتعاد لهم + تنبيه |
| إعادة الإرسال نجحت | التنبيه يقول "اتصلّح" |

### ١٣) بناء التقرير والسلايدز

| الحالة | المتوقع |
|--------|---------|
| الإيميل | نسخة HTML + نسخة نصية حقيقية من غير وسوم |
| فقرة الـ AI | مش موجودة خالص |
| `Report Stats` | يحسب التحسّن والتراجع صح من غير برومبت |
| حجم البحث | قيمة الإكسل تظهر، والتعديل اليدوي يكسب |
| السلايدز | سلايد لكل كلمة + اسم الكلمة + سطر حجم البحث |
| خانة فاضية | ما ترسمش عمود في الرسم البياني |
| عرض فيه ٠ سلايد | نود الحذف مايوقعش |

### ١٤) الفروق الأسبوعية

| الحالة | المتوقع |
|--------|---------|
| ترويسات `2025-W35` و `2025-08` مع بعض | الأسبوعي يقرا الأسابيع بس |
| عنوان الإيميل | `أسبوع 25 – 31 أغسطس 2025` |
| السلايد | كابشن سطرين (من/إلى) + السنة تحتيه |

### ١٥) قوائم الكلمات

| الحالة | المتوقع |
|--------|---------|
| العوجان | ٣٥ كلمة / ٦ أقسام |
| شوق | ٢٥ كلمة / ٨ أقسام + روابط الأقسام المعروفة |
| الأسبوعي مقابل الشهري | نفس القايمة بالظبط |
| حجم البحث | من الإكسل (`الدماغ والحبل الشوكي = 1900`) |

### ١٦) تنبيه فشل Search Console

| الحالة | المتوقع |
|--------|---------|
| توكن منتهي (`401 invalid_grant`) | يقول اعمل Reconnect ويسمّي الكريدنشيال |
| الموقع مسجّل كـ Domain Property | يقول غيّر `SITE_URL` **ويديك النص الصح** |
| الحساب مالوش صلاحية | يقول ضيفه من المستخدمون والأذونات |
| `429` أو عطل شبكة | يتصنّف `temporary` ويقول شغّله تاني |
| أي حالة | جدول بكل المواقع اللي الحساب شايفها + رسالة جوجل الخام |
| أي حالة | تطمين إن الشيت ما اتلمسش + نسخة نصية |

## المستوى ٣ — اختبار يدوي في n8n قبل التفعيل

بالترتيب ده بالظبط:

### أ) قبل أي استيراد

1. خد **نسخة من الشيتات الأربعة** (ملف → عمل نسخة). دي شبكة الأمان الوحيدة لو حصل حاجة.
2. خد نسخة من ملفات n8n القديمة (تصدير) — عشان الرجوع لو لزم.

### ب) الاستيراد

3. استورد `dist/*.json` كـ **workflows جديدة** (مش استبدال) وسيبها **متوقفة (Inactive)**.
4. اتأكد إن الكريدنشيالز اترطبت لوحدها:
   * `googleOAuth2Api` → `rabeh.seven.b`
   * `smtp` → `Rabeh SMTP`

### ج) رن جاف بمعزل عن الشيت الحقيقي

5. في `Config`، غيّر `SPREADSHEET_ID` و `PRESENTATION_ID` لنسخ **تجريبية**.
6. شغّل من `Manual Trigger`.
7. افتح مخرجات `Validate Data` وشوف:
   * `ok = true`
   * `quality.coverage` قريبة من ١
   * `quality.tally.holes = 0`
   * `quality.freshnessSource = "gsc"`
   * `problems` فاضية
   * راجع `warnings` — ملاحظات `pageMisses` طبيعية للعوجان (مفيش روابط)
8. افتح `quality.failures` — لو فيها حاجة، اقرا السبب الحرفي.
9. راجع الشيت التجريبي: عدد الصفوف = عدد الكلمات + ١، وعمود `Article` موجود، ومفيش صفوف من القايمة القديمة.
10. راجع العرض التجريبي: عدد السلايدز = عدد الكلمات، وحجم البحث ظاهر مش `—`.

### د) اختبار مسار الإيميل

11. راجع مخرجات `Delivery Audit`:
    * `accepted` فيها إيه بالظبط؟
    * `missing` فيها عنوان الجيميل؟
    * `smtpResponse` بيقول إيه حرفيًا؟
12. لو الجيميل في `missing` → `Resend Individually` هيشتغل، وهيوصلك إيميل حالة توصيل. **رد السيرفر في الإيميل ده هو التشخيص النهائي** — كمّل من [EMAIL-DELIVERABILITY.md](EMAIL-DELIVERABILITY.md).
13. افتح الإيميل الواصل واعمل «إظهار الأصلي» في جيميل وشوف `SPF` و `DKIM` و `DMARC`.

### هـ) اختبار البوابة صناعةً

14. في `Config` غيّر `MIN_COVERAGE` لـ `1.01` مؤقتًا وشغّل.
15. المتوقع: البوابة تقفل، `Data Alert Email` يتبعت، **والشيت التجريبي ما يتغيرش خالص**.
16. رجّع `MIN_COVERAGE` لـ `0.98`.

### و) التفعيل

17. رجّع `SPREADSHEET_ID` و `PRESENTATION_ID` للقيم الحقيقية.
18. شغّل يدوي مرة على الحقيقي وراجع الشيت والعرض والإيميل.
19. فعّل الـ workflow (`Active`).
20. **وقّف النسخ القديمة** — لو فضلت شغالة هتكتب على نفس الشيتات وتلغي التصليح.

### ز) متابعة أول أسبوعين

* راجع `quality.holes` في كل رن — المفروض تفضل ٠.
* راجع `quality.suspicious` — لو فيها خانات كتير، يبقى في كلمة رابطها اتغيّر.
* راجع `quality.pageMisses` — دي بتقولك أنهي كلمة بتترتب على صفحة غير المستهدفة (معلومة SEO مفيدة لوحدها).

## مواعيد التشغيل

| التقرير | الموعد القديم | الموعد الجديد | ليه |
|---------|--------------|--------------|-----|
| الشهري | يوم ٣ من الشهر، ٨ ص | زي ما هو | بيانات الشهر اللي فات جاهزة |
| الأسبوعي | **الإثنين** ٨ ص | **الأربع** ٨ ص | الأسبوع بيقفل الأحد وبيانات جوجل النهائية بتاخد ٢–٤ أيام |

حتى مع الموعد الجديد، نود `GSC Freshness` هو الحكم — لو البيانات لسه ما وصلتش،
الأسبوع ده بيتأجّل للرن الجاي بدل ما يطلّع أرقام ناقصة.
