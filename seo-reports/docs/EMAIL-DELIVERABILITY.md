# ليه الإيميل مابيوصلش على جيميل — وإزاي تصلّحها

الأوتوميشن دلوقتي بيقولك **بالظبط** إيه اللي بيحصل بدل ما يفشل في صمت.
الملف ده بيشرح إزاي تقرا التشخيص وتصلّح الجزء اللي بره الأوتوميشن.

---

## الأول: إيه اللي الأوتوميشن بيعمله دلوقتي

بعد ما يبعت التقرير، نود `Delivery Audit` بيقرا **رد سيرفر الـ SMTP الحقيقي**:

```
expected      = كل المستلمين (To + CC)
accepted      = اللي السيرفر قال إنه قبلهم
rejected      = اللي رفضهم صراحةً
missing       = expected - accepted   ← دول المشكلة
smtpResponse  = رد السيرفر الحرفي
```

أي حد في `missing` بيتبعتله **إيميل منفصل لوحده**، وبعدين بيوصلك إيميل
حالة توصيل فيه جدول: مين وصله ومين لأ ورد السيرفر لكل واحد.

**رد السيرفر ده هو التشخيص.** كمّل حسب اللي مكتوب فيه:

---

## الحالة ١: `550 Relay denied` / `551 User not local` / `530 Relaying not allowed`

**المعنى:** سيرفر `rabeh.org` مش مسموح له يوصّل لعناوين بره الدومين
باستخدام الحساب ده. عشان كده `M.gamal@rabeh.org` بيوصل و `@gmail.com` لأ.

**الحل — عند مزوّد الاستضافة/البريد:**

1. افتح إعدادات حساب `M.gamal@rabeh.org` وفعّل **External Relay** أو
   **Allow sending to external domains** (الاسم بيختلف: cPanel/Plesk/Zimbra/Exchange).
2. لو السيرفر Exchange أو Microsoft 365: راجع **Receive Connector** أو
   **Anonymous relay** للـ IP بتاع سيرفر n8n.
3. لو فيه allow-list للـ IPs → ضيف IP سيرفر n8n.
4. لو المزوّد بيرفض يفتح الريلاي → استخدم بدايل الحالة ٤ تحت.

**اختبار سريع من سيرفر n8n:**

```bash
# غيّر SMTP_HOST والبورت لبتوعك
swaks --server SMTP_HOST:587 --tls \
      --auth-user 'M.gamal@rabeh.org' --auth-password 'PASSWORD' \
      --from 'M.gamal@rabeh.org' --to 'YOUR@gmail.com' \
      --header 'Subject: relay test'
```

لو ظهر `550` في مرحلة `RCPT TO` → الريلاي مقفول، والباقي مش هيفرق.

## الحالة ٢: `535 Authentication failed` / `534` / `454 TLS`

**المعنى:** الاتصال نفسه واقع — بيانات الدخول أو البورت أو TLS.

**الحل:**

1. n8n → Credentials → `Rabeh SMTP`:
   * `User` **لازم يساوي بالظبط** `M.gamal@rabeh.org` (نفس اللي في `MAIL_FROM`).
   * البورت: `587` مع STARTTLS، أو `465` مع SSL. **مش `25`**.
   * لو الباسورد اتغيّر أو فيه 2FA → اعمل **App Password** واستخدمه.
2. لو المزوّد جوجل ووركسبيس → لازم App Password، الباسورد العادي مرفوض.

## الحالة ٣: السيرفر قبل الرسالة (`250 OK`) بس جيميل مش شايفها

`accepted` فيها عنوان الجيميل، ومحدش شايف الإيميل → **الرسالة اتقبلت
واترمت عند جيميل** (سبام أو حجب صامت). دي مشكلة سمعة و DNS.

### الفحص الأول: افتح الأصلي في جيميل

في أي إيميل واصل: القايمة (⋮) → **إظهار الأصلي**. هتلاقي:

```
SPF:   PASS   with IP xx.xx.xx.xx
DKIM:  PASS   with domain rabeh.org
DMARC: PASS
```

أي واحدة فيهم `FAIL` أو `NEUTRAL` أو `SOFTFAIL` = دي المشكلة.

### أ) SPF — لازم يشمل سيرفر n8n

```bash
dig +short TXT rabeh.org | grep spf
```

المفروض ترجع سجل واحد بس شبه ده:

```
v=spf1 include:_spf.YOURPROVIDER.com ip4:<IP سيرفر n8n> ~all
```

* **الغلط الشائع:** سيرفر n8n بيبعت من IP مش موجود في SPF → جيميل يفشّل SPF.
* **غلط تاني:** أكتر من سجل SPF على نفس الدومين = SPF بيفشل كله. لازم سجل واحد.
* `~all` (softfail) مقبول، `-all` (hardfail) أحسن بعد ما تتأكد إن كل مصادر الإرسال متسجّلة.

### ب) DKIM — لازم يكون مفعّل وموقّع

```bash
dig +short TXT default._domainkey.rabeh.org
# جرّب السيلكتورات التانية لو فاضية: selector1، google، mail، k1
```

لو فاضية → **DKIM مش مفعّل**، وده لوحده كفاية إن جيميل يرمي الرسالة في السبام
لأي دومين بيبعت آليًا. فعّله من لوحة مزوّد البريد وحط سجل TXT اللي هيديهولك.

### ج) DMARC — لازم يكون موجود

```bash
dig +short TXT _dmarc.rabeh.org
```

المفروض:

```
v=DMARC1; p=none; rua=mailto:dmarc@rabeh.org
```

ابدأ بـ `p=none` (مراقبة بس) لحد ما SPF و DKIM يعدّوا، وبعدين اطلع لـ `p=quarantine`.

**مهم:** DMARC محتاج **alignment** — الدومين في `From:` لازم يطابق دومين SPF أو DKIM.
`MAIL_FROM` في الأوتوميشن هو `M.gamal@rabeh.org`، فلازم SMTP يبعت باسم `rabeh.org`.
لو السيرفر بيبعت بـ envelope-from على دومين تاني → DMARC هيفشل رغم إن SPF ناجح.

### د) سجل PTR (Reverse DNS)

```bash
dig +short -x <IP سيرفر n8n>
```

المفروض يرجع اسم على دومينك. لو رجّع اسم عام بتاع الاستضافة
(زي `ec2-1-2-3-4.compute.amazonaws.com`) أو مرجّعش حاجة → جيميل بيقلل الثقة.
اطلب من مزوّد الاستضافة يظبط PTR.

### هـ) هل الـ IP في قوايم الحظر؟

```bash
# افحص على mxtoolbox.com/blacklists.aspx أو:
dig +short <IP معكوس>.zen.spamhaus.org
```

أي رد = الـ IP محظور. اطلب إزالة من الموقع اللي حاظره.

### و) فحص شامل في خطوة واحدة

ابعت إيميل من الأوتوميشن لعنوان من **[mail-tester.com](https://www.mail-tester.com)**
وشوف السكور. أي حاجة تحت **٨/١٠** لازم تتصلّح.

## الحالة ٤: المزوّد رافض يفتح الريلاي — البدايل

### البديل أ: خدمة إرسال مخصّصة (الأنضف)

اعمل حساب على **[Brevo](https://www.brevo.com)** (٣٠٠ إيميل/يوم مجانًا) أو
**Mailgun** أو **Amazon SES**، وثّق دومين `rabeh.org` عندهم (هيدّوك سجلات
SPF + DKIM جاهزة)، وبعدين في n8n:

```
Credentials → SMTP جديد:
  Host: smtp-relay.brevo.com
  Port: 587
  User: <من لوحة الخدمة>
  Pass: <مفتاح SMTP>
```

بعدين في نودات الإيميل الأربعة غيّر الكريدنشيال للجديد. **مش محتاج تغيّر أي
كود** — `MAIL_FROM` يفضل `M.gamal@rabeh.org` طالما الدومين موثّق عندهم.

الخدمات دي بتدّيك كمان **تتبّع فتح وبونس** — يعني هتعرف لو الإيميل وصل واتفتح.

### البديل ب: الإرسال من Gmail API بنفس حساب جوجل الموجود

الأوتوميشن أصلاً مربوط بكريدنشيال جوجل (`rabeh.seven.b`) للـ Search Console والشيتات.
ينفع تضيف صلاحية `gmail.send` عليه وتبعت عن طريق Gmail API. **العيب:** المُرسِل
هيبقى حساب الجيميل ده مش `M.gamal@rabeh.org` — إلا لو الحساب جزء من
Google Workspace على دومين `rabeh.org` (ساعتها ده أحسن حل على الإطلاق).

## شيك ليست سريعة

- [ ] `Delivery Audit` بيقول إيه في `smtpResponse`؟ — ده نقطة البداية
- [ ] المستخدم في كريدنشيال SMTP = `M.gamal@rabeh.org` بالظبط
- [ ] البورت `587` (STARTTLS) أو `465` (SSL) — مش `25`
- [ ] الريلاي الخارجي مفتوح للحساب ده
- [ ] `dig TXT rabeh.org` فيه **سجل SPF واحد** وشامل IP سيرفر n8n
- [ ] `dig TXT <selector>._domainkey.rabeh.org` بيرجّع مفتاح DKIM
- [ ] `dig TXT _dmarc.rabeh.org` بيرجّع سياسة
- [ ] `dig -x <IP>` بيرجّع اسم على دومينك
- [ ] الـ IP مش في قوايم الحظر
- [ ] سكور mail-tester ≥ ٨/١٠

## اللي الأوتوميشن ظبطه من ناحيته

دي كلها اتنفّذت وبيتأكد منها الفحص الساكن في كل بناء:

| # | التغيير | الأثر |
|---|---------|------|
| ١ | نسخة **نص عادي** جنب الـ HTML (`emailFormat: both`) | HTML لوحده من أكبر عوامل رفع سكور السبام |
| ٢ | إلغاء توقيع n8n (`appendAttribution: false`) | شيل سطر إعلاني ولينك خارجي من رسالة تجارية |
| ٣ | `From` باسم عرض: `"رابح — تقارير SEO" <M.gamal@rabeh.org>` | العنوان مطابق للمستخدم المصادَق عليه — شرط SPF/DMARC |
| ٤ | `Reply-To` صريح | بيقلل احتمال التصنيف كسبام |
| ٥ | شيل التكرار بين To و CC | بعض السيرفرات بترفض المستلم المكرر |
| ٦ | تحقق من صيغة كل إيميل | عنوان غلط واحد مايوقفش الإرسال كله |
| ٧ | إزالة الإيموجي من عناوين التنبيهات | `⚠️` في الـ subject بيرفع سكور السبام |
| ٨ | تدقيق التوصيل + إعادة إرسال فردية | الفشل الصامت بقى تنبيه فيه رد السيرفر الحرفي |
| ٩ | تنبيهات التوصيل بتروح لعناوين الدومين الداخلي | ضمان إن التنبيه نفسه يوصل |

**اللي مش قادر يتظبط من الأوتوميشن:** SPF، DKIM، DMARC، PTR، صلاحية الريلاي،
وسمعة الـ IP. دي كلها في DNS وإعدادات السيرفر — والشيك ليست فوق بتغطيها بالترتيب.
