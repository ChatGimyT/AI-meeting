# الخطة المعمارية — لماذا بُني المحرك هكذا؟

هذه الوثيقة تشرح **القرارات** لا الشيفرة. اقرأها قبل أن تعدّل شيئًا جوهريًا.

---

## ١. المشكلة الحقيقية

البرومبتات الأربعة الأصلية (الجيم الأساسي، برومبت الكتابة، برومبت التحديث، برومبت التحقق)
تحتوي على أكثر من **١٤٠ شرطًا** موزّعة بين: بنية، لغة، سيو، AEO، GEO، E-E-A-T، استشهادات،
ربط داخلي، سوق محلي، إقناع، وطول. وضعها كلها في نداء واحد يُنتج ثلاث مشكلات:

1. **الانتباه المُوزَّع**: كلما زادت الشروط في نداء واحد، سقط بعضها بصمت.
2. **المجاملة الذاتية**: النموذج الذي كتب النص هو نفسه الذي يقيّمه، فيعطي ٩/١٠ لنص ٦/١٠.
3. **الشروط الرقمية**: «١٨٠٠–٢٠٠٠ كلمة» و«لا فقرة تتجاوز ١٥٠ كلمة» ليست مسائل رأي،
   والنموذج سيّئ في العدّ.

الحل ليس برومبتًا أذكى، بل **مؤسسة**: تقسيم عمل، وسلطة حسم، وقياس مستقل، ودورات.

## ٢. المبادئ الخمسة

### أ. الفصل بين من يكتب ومن يحكم
لا شخصية تكتب وتقيّم نفسها. الكاتب يكتب، والناقد ينقد، والمجلس يحسم.
وكل ناقد يقيّم **بنوده فقط** (`scores_for`)، فلا يوجد رأي عام مائع.

### ب. ما يمكن قياسه لا يُترك لنموذج لغوي
عقدة `🔍 Mechanical Inspector` كود JavaScript خالص. تقيس ٢٣ فحصًا:
عدد الكلمات، طول كل فقرة، إجابة كل H2، أطوال الميتا، تكرار الكلمة المفتاحية وصياغتها الحرفية،
عدد أسئلة FAQ، الروابط المكسورة، روابط الصفحة الرئيسية، **الروابط المختلقة**،
استخدام كل رابط داخلي وتوزيعه، مصادر مذكورة في القائمة ولم تُستشهد داخل النص،
تتابع الفقرات بلا قوائم، العبارات الممنوعة، المفردات العامية، ونسب مئوية بلا أدلة.

مخرجاته **حقائق**: تدخل موجز التعديل إجباريًا، ولا يملك رئيس المجلس صلاحية تجاهلها.

### ج. لا رقم بلا مصدر — ميكانيكيًا لا وعظيًا
سلسلة ثلاثية قبل أن يرى الكاتب أي رقم:

```
🔎 بحث حقيقي (web_search) → 🌐 طلب HTTP لكل رابط → 🧪 مدقق حقائق يرفض
```

ثم فحص `links_whitelisted` يرفض أي رابط في النص خارج حزمة الأدلة المعتمدة.
النتيجة: **اختلاق مصدر يصبح مستحيلًا بنيويًا**، لا مجرد ممنوع في البرومبت.

### د. التعارض يُحسم كتابةً
تسعة نقاد ينتجون ملاحظات متناقضة بالضرورة (كاتب الإعلانات يريد CTA أقوى، وناقد المقال
التعليمي يرفض البيع). بلا سلطة حسم يدور المقال بلا نهاية.
رئيس المجلس مُلزَم بإخراج `conflicts_resolved` و`rejected_notes` **مع السبب**،
ويدمج الباقي في موجز واحد ≤ ١٢ بندًا. المحضر يوثّق كل ذلك.

### هـ. البوابة لا تثق بأحد
`🚪 Chair Ruling & Gate` يعيد حساب الشروط بنفسه:
كل بند ≥ العتبة، صفر أخطاء حرجة، المفتش الآلي ناجح.
قرار رئيس المجلس مُدخل في القرار، وليس القرار.

## ٣. لماذا هذه البنية في n8n تحديدًا؟

### تنفيذ لكل عنصر بدل حلقات `splitInBatches`
عقد n8n تُنفَّذ **مرة لكل عنصر دخل**. لذلك عقدة الأجندة تُخرج ٩ عناصر،
وعقدة `🧠 LLM · Review Panel` تُنفَّذ ٩ مرات تلقائيًا.
هذا يلغي الحاجة لحلقات `splitInBatches` ومشاكل `reset` عند وجود دورة خارجية.

### تناوب: أجندة ← نداء ← محضر
كل مرحلة تتبع النمط نفسه:

| العقدة | الدور |
|---|---|
| `🗓️ Agenda: X` | تبني نص الطلب من الحالة، وتُخرج عنصرًا (أو عناصر) جاهزًا للـ HTTP |
| `🧠 LLM · X` | ينفّذ النداء |
| `🗓️ Agenda: Y` / `📋 Minutes: X` | يقرأ الرد، يحدّث الحالة، يكتب المحضر، ويبني الأجندة التالية |

دمج «المحضر» و«الأجندة التالية» في عقدة واحدة قلّص العدد من ٤٠ عقدة كود إلى ٢٢،
واستُثني من الدمج ما هو **هدف دورة**: `🗓️ Agenda: Draft` (تعود إليها إعادة البناء)
و`🔍 Mechanical Inspector` (تعود إليها دورة التعديل).

### استرجاع الحالة بعد نداء HTTP
عقدة HTTP في n8n تستبدل محتوى العنصر بالرد، فتضيع الحالة.
لذلك كل عقدة محضر تسترجعها من عقدة الأجندة المقابلة لها:

<div dir="ltr">

```js
const call = $('🗓️ Agenda: Draft').first();
const s    = call.json.state;
```

</div>

وهذا سبب إلزامية **عدم تغيير أسماء العقد**. `tools/validate.mjs` يفحص هذه المراجع آليًا.

### الدورتان
- **دورة التعديل**: `📋 Minutes: Revise → 🔍 Mechanical Inspector` — النص المعدّل يمر بالفحص والطاولة من جديد.
- **دورة إعادة البناء**: `♻️ Restart Session → 🗓️ Agenda: Draft` — يُمسح النص ويُعاد بناؤه من المخطط
  محمّلًا بقائمة الأخطاء التي لا يجوز تكرارها.

الحماية من اللانهاية: `gate.max_rounds` و`gate.max_restarts`،
ومسار `exhausted` يسلّم أفضل نسخة متاحة **مع تقرير تحفّظات** بدل أن يفشل صامتًا.

## ٤. حراس الأمان

| الخطر | الحارس |
|---|---|
| النموذج يرد بنص بدل JSON | `H.grabJson` بمسح أقواس متوازن يراعي النصوص والهروب |
| تمريرة تحرير تُرجع نصًا مبتورًا | ترفض العقدة أي ناتج أقصر من ٦٠٪ وتُبقي النسخة السابقة |
| فشل نداء API | `retryOnFail` ×٣ + `onError: continueRegularOutput` + تسجيل الخطأ في `state.errors` |
| مواقع تحجب الفحص الآلي | ٤٠٣ و٤٠٥ و٤٢٩ لا تُعتبر روابط مكسورة |
| ملف تعريفي يرث قيمة لا يريدها | `null` تلغي القيمة صراحةً، و`undefined` تعني «لا تجاوز» |
| كتابة بلا مدخلات كافية | `⚙️ Open Session` يوقف الجلسة ويعيد قائمة الناقص |

## ٥. بنية المستودع

<div dir="ltr">

```
src/
  lib/helpers.js          ← مكتبة H المشتركة (تُحقن في كل عقدة كود)
  profiles/*.mjs          ← الشخصيات والقواعد والعتبات (ما ستعدّله عمليًا)
  stages/*.js             ← جسم كل عقدة كود، ملف لكل مرحلة
build/
  blueprint.mjs           ← العقد والوصلات والمواضع والملاحظات
  build.mjs               ← يجمّع كل ما سبق في ملف n8n واحد
tools/
  validate.mjs            ← فحص بنيوي + فحص مراجع $('…')
  simulate.mjs            ← محاكي n8n مصغّر
  mock-llm.mjs            ← ردود وهمية لكل شخصية
dist/
  ai-editorial-boardroom.json   ← الملف الجاهز للنسخ واللصق
```

</div>

**لماذا مستودع مصادر وليس ملف JSON فقط؟**
لأن مكتبة المساعدات تتكرر في ٢٢ عقدة. تعديلها يدويًا داخل JSON بحجم ٦٥٠ كيلوبايت
مستحيل عمليًا. `npm run build` يحل ذلك: تعدّل ملفًا واحدًا، ويُعاد توليد الـ workflow كاملًا.
ومن يريد الملف جاهزًا فقط يأخذ `dist/` ويتجاهل الباقي.
