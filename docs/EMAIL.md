# 📧 تسليم التقارير بالبريد — ولماذا لم تكن تصل إلى Gmail

## الخلاصة أولًا

**العرض:** التقارير تصل إلى العناوين على دومين الشركة، ولا تصل إلى عناوين Gmail.

**السبب في ٩٩٪ من الحالات ليس الكود، بل النـاقل (transport).** رسالة تصل إلى
`someone@rabeh.org` وتُرفض إلى `someone@gmail.com` تعني أن الرسالة **لم تغادر
حدود دومينك أصلًا** — وذلك يحدث لأسباب أربعة معروفة، مرتبة بترتيب احتمالها.

---

## جدول الأعطال — ابدأ من الأعلى

### ١. Google Workspace SMTP relay مضبوط على «Only addresses in my domains» ⭐

**الاحتمال الأكبر بفارق كبير.**

في `Admin console → Apps → Google Workspace → Gmail → Routing → SMTP relay
service`، لخدمة الترحيل خيار **Allowed senders / recipients**. القيمة
الافتراضية في كثير من الإعدادات هي **«Only addresses in my domains»**.

بهذا الإعداد يقبل الخادم رسالتك، **يعيد `250 OK`**، ثم يُسقط كل مستلم خارج
دوميناتك. فتظهر الأتمتة ناجحة في n8n بينما لم يصل شيء. هذا بالضبط ما يجعل
العطل محيّرًا: **لا رسالة خطأ في أي مكان.**

**الحل — أحدهما:**
- **(أ)** غيّر الخيار إلى **«Any addresses»** في نفس الشاشة، أو
- **(ب) الأفضل والأسرع:** استخدم مسار **Gmail API** الموجود الآن في الـ workflow
  (`📧 Gmail: Send Report`) بدل SMTP. Gmail API يرسل من صندوق المستخدم مباشرة
  ولا يمرّ بخدمة الترحيل أصلًا، فلا يعرف هذا القيد.

### ٢. اعتماد Gmail بصلاحية ناقصة

عقدة Gmail تحتاج نطاق **`https://www.googleapis.com/auth/gmail.send`**.
اعتماد أُنشئ بنطاق قراءة فقط يفشل — أحيانًا بخطأ غامض لا يذكر الصلاحية.

**الحل:** في n8n → Credentials → Gmail account، احذف الاعتماد وأعد ربطه،
وتأكد أن شاشة موافقة جوجل تطلب صلاحية **«Send email on your behalf»**.

### ٣. SPF · DKIM · DMARC غير مضبوطة على الدومين

هذه تشرح العرض بدقة: **الرسائل داخل دومينك لا تُفحص لأنها لا تغادر الخادم،
والخارجة تُفحص فتُرفض أو تُصنَّف spam.** فتصل إلى `@rabeh.org` وتختفي في
`@gmail.com` — وقد تكون في مجلد Spam لا مرفوضة.

**قبل أي شيء آخر: افحص مجلد Spam في حساب الجيميل.** إن كانت الرسائل هناك،
فالعلة هنا لا في الترحيل.

**الحل:** اضبط السجلات الثلاثة على الدومين، ثم اختبر عبر أي أداة فحص SPF/DKIM.

### ٤. قائمة دومينات مسموحة داخل الكود

**في هذا المحرك هذه العلة غير موجودة، ولن تعود:**

<div dir="ltr">

```js
delivery: {
  email: {
    allow_domains: [],   // فارغة = بلا أي تقييد. هذا هو الافتراضي المقصود.
    block_domains: []    // فارغة = لا حجب لأحد.
  }
}
```

</div>

`allow_domains` **فارغة افتراضيًا ولا تُفعَّل إلا إن ملأتها بنفسك عمدًا**، وهناك
اختبار دائم في `npm test` يفشل إن حُجب أي عنوان بسبب دومينه:

<div dir="ltr">

```
✅ وصل إلى عنوان على دومين العميل
✅ وصل إلى عنوان Gmail
✅ لا قائمة دومينات تحجب أحدًا
```

</div>

## كيف يتعامل المحرك مع العناوين

### مصادر العناوين — تُدمج كلها

| المصدر | الاستخدام |
|---|---|
| عمود **«مستلمو التقرير»** في الشيت | لكل مقال على حدة |
| عمود **«نسخة إلى»** | نسخة CC |
| `delivery.email.to` في الملف التعريفي | مستلمون ثابتون لكل تشغيلات العميل |
| `recipients` / `email_to` في الـ webhook أو الطلب | للدمج مع أنظمة أخرى |

الفواصل المقبولة: سطر جديد · فاصلة عربية أو لاتينية · فاصلة منقوطة · `|`.
والصيغ المقبولة: `a@b.com` · `الاسم <a@b.com>` · `mailto:a@b.com`.

### التطبيع — ولماذا هو بهذا الشكل تحديدًا

| القاعدة | السبب |
|---|---|
| **الدومين يُخفَّض حرفه، والجزء المحلي لا** | الدومينات غير حساسة لحالة الأحرف بالمعيار، والجزء المحلي **قد يكون حساسًا** على بعض الخوادم. تخفيض الاسم كله خطأ شائع يكسر عناوين صحيحة |
| **`gmail.com` و`googlemail.com` نفس الصندوق** | لإزالة التكرار فقط |
| **النقاط و`+tag` في Gmail تُتجاهل عند إزالة التكرار** | `a.b+x@gmail.com` و`ab@gmail.com` نفس الصندوق — لكن **يُرسَل إلى العنوان كما كتبته**، لا إلى الصيغة المختصرة |
| **التحقق بصيغة عامة تقبل كل TLD** | لا قائمة دومينات مسموحة مخفية داخل صيغة التحقق |

### كل استبعاد له سبب مكتوب

لا يختفي عنوان بصمت أبدًا. كل عنوان مستبعد يُسجَّل في `dropped_recipients`
وفي عمود **«حالة الإرسال»** بالشيت:

<div dir="ltr">

```
⛔ استُبعد rabehmarketing@googlemail.com — مكرر — أُرسل مرة واحدة
⛔ استُبعد not-an-email — لا يحتوي على @ بصيغة صحيحة
```

</div>

فسؤال «لماذا لم يصل التقرير لفلان؟» له جواب مكتوب دائمًا، بلا تخمين.

## اختيار الناقل

<div dir="ltr">

```js
delivery: { email: { transport: 'gmail' } }   // أو 'smtp'
```

</div>

| | `gmail` (الافتراضي) | `smtp` |
|---|---|---|
| العقدة | `📧 Gmail: Send Report` | `📧 SMTP: Send Report` |
| الاعتماد | Gmail OAuth2 بصلاحية `gmail.send` | SMTP account |
| **الوصول لـ Gmail وغيره** | ✅ بلا قيد | ⚠️ حسب إعداد خادمك |
| يمرّ بخدمة SMTP relay | ❌ لا | ✅ نعم — **وهنا يقع القيد** |
| المُرسِل | صندوق الحساب المربوط | `from_email` في الملف التعريفي |

**التوصية: `gmail`.** يتجاوز السبب الأول والأكثر شيوعًا للعطل بالكامل.

## الإعداد في n8n — ٣ دقائق

1. **Credentials → New → Gmail OAuth2 API**، سمّه `Gmail account`، واربطه
   بالحساب الذي سيُرسل. تأكد من صلاحية **Send email on your behalf**.
2. افتح عقدة **`📧 Gmail: Send Report`** واختر الاعتماد (سيقترحه n8n).
3. في الشيت، املأ عمود **«مستلمو التقرير»** بعناوين مفصولة بفواصل — **ضع
   عنوان Gmail بينها في أول تشغيلة تجريبية للتأكد.**
4. (لمسار SMTP) اربط اعتماد `SMTP account` بعقدة `📧 SMTP: Send Report`
   واضبط `transport: 'smtp'` و`from_email` في الملف التعريفي.

للبناء باعتمادات جاهزة:

<div dir="ltr">

```bash
node build/build.mjs \
  --gmail-credential-id=YOUR_ID --gmail-credential-name="Gmail account"
```

</div>

## متى يُرسَل التقرير ومتى لا؟

**البريد آخر عقدة في السلسلة، بعد بوابة الأرقام مباشرة.** لا يُرسل رقم واحد
قبل أن يمرّ على الطبقات السبع ([`NUMBERS-AUDIT.md`](NUMBERS-AUDIT.md)).

| حكم البوابة | ما يُرسَل |
|---|---|
| `clear` | التقرير كاملًا + المقال + بطاقة الأرقام المعتمدة |
| `clear_with_notes` | التقرير كاملًا + الملاحظات (أرقام تحتاج تأكيد العميل) |
| `hold` | **إشعار حجز فقط** — أسباب الحجز وجدول الأرقام المخالفة، **والمقال غير مرفق عمدًا** |

قرار حجب المقال عند `hold` مقصود: إرسال تقرير قد يُصدَّق وفيه رقم خاطئ أخطر
من عدم إرسال شيء. والعميل يعرف فورًا أن هناك ما يحتاج تدخلًا.

**الحالات التي لا يُرسل فيها بريد إطلاقًا** (وكلها تُكتب في عمود «حالة الإرسال»):

- `delivery.email.enabled: false`
- لا مستلم صالح — العمود فارغ والملف التعريفي فارغ
- `send_when: 'clear_only'` والبوابة محجوزة
- الطلب رُفض عند المدخل فلا حزمة تسليم أصلًا
